## Q1 — may ticket 16 report the kill-holder adversary's own victim apart from `failed-launches`?

Facts: S3's kill-holder adversary SIGKILLs one of the round's own launches (the lock holder). Before ticket 16, every launch with a non-zero exit counted as failed, so the victim always counted and budget 0 was unreachable for any kit. Ticket 16 adds `launchOutcomes()`: the launch whose pid equals the adversary's recorded `killed` pid and that exited non-zero is reported under `killedByAdversary` and not under `failedLaunches`; every other non-zero launch still counts. Matched by pid only (one victim per round). Measured on linux (implementer, 3 tip runs vs 7 branch runs): with the new counting the integration tip still fails S3/short 2/7/2 and S3/hung 10/11/10 launches (old counting 3/8/3 and 11/12/11), and ticket 16's tree is 0 in 7/7. Ticket 16 then deletes its `failed-launches` and `stale-lock-after-round` names from S3/short and S3/hung on both legs (they become unowned: any RED fails). Separately, S4's harness no longer fails when the stale lock it planted is already gone (ticket 16's kit now takes a dead holder's lock over); it records `staleLockLeft` instead of failing on `unlinkSync`. No budget value, check name, repetition count or bound changes.

Recommendation: accept both as measurement corrections, not budget loosenings: the victim launch is ended by the scenario itself and cannot exit 0 under any kit, and the budget text "incl. a killed lock holder" asks that the kill does not make any OTHER launch fail; the tip stays RED under the new counting, so the check keeps its power. Conditions: (1) the spec §18 S3 row and METRICS state the rule ("the adversary's own victim, matched by pid, is reported as `killedByAdversary` and is never a failed launch"); (2) `killedByAdversary` must contain at most one launch per round, and a round where the adversary reports a kill but no launch matches that pid is a harness failure, not GREEN (ticket 16 adds the test if missing); (3) the S4 `staleLockLeft` value is recorded in notes, not judged, until ticket 17 owns S4's lock checks.
