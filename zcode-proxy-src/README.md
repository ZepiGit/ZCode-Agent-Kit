# ZCode Proxy

**English** | [中文](README.zh-CN.md) | [Español](README.es.md) | [日本語](README.ja.md) | [Deutsch](README.de.md)

This directory vendors the **zcode-proxy** from
[TriDefender/zcode-api](https://github.com/TriDefender/zcode-api) — pinned at
v4.6.4, commit `9a5cebe07c5255faa675075fa37632d4dea733fa` (2026-09-11), MIT
license (upstream ships no LICENSE file). Version, commit and local
modifications are documented in [`../MANIFEST.md`](../MANIFEST.md); local
patches live in [`../patches/`](../patches/).

This README and its [Chinese translation](README.zh-CN.md) describe the
component **as it is used inside the ZCode Agent Kit**. The upstream project
also documents standalone features such as Android, Docker, off-peak channels
and trial claiming, which the kit does not use.

## Role inside the kit

The proxy is the kit's model gateway. It accepts OpenAI chat-completions,
Anthropic messages and OpenAI Responses requests on **`http://127.0.0.1:8457`**
and forwards them to the Z.AI gateway using your logged-in ZCode Desktop
account (start-plan, the same quota as ZCode Desktop).

The optional `auth.accounts.enabled` pool accepts multiple authorized
accounts. New requests refresh the authoritative pool before dispatch and
only explicit `1005`, `1113` or `3001` quota signals permit one sequential
failover attempt. With the feature enabled, `zcode-kit auth login zai` saves
newly authorized accounts as additional profiles; logging into the same
account refreshes its existing profile. Use `zcode-kit accounts` or
`zcode-proxy auth accounts` with `pause|resume`,
`explain`, `doctor`, `quota` and `--live`; see
[`../docs/ACCOUNT_ROTATOR.md`](../docs/ACCOUNT_ROTATOR.md) for key setup,
migration and recovery rules.

- Addresses/formats: `POST /v1/chat/completions`, `POST /v1/messages`,
  `POST /v1/responses`, `GET /v1/models`, `GET /health`, `GET /quota`,
  authenticated `GET /accounts/status` and `GET /accounts/quota`
- Authentication: `Authorization: Bearer <contents of .proxykey>` — the local key
  is generated by `zcode-kit setup` (kit directory for release/source installs;
  separate state directory for npm installs)
- Lifecycle: managed by `node proxy\zcode-proxy-manager.mjs start|stop|restart|status|doctor|logs`
  (loopback-only bind, fail-closed stop, log rotation — see the root README)
- Login renewal: `zcode-kit auth login zai`; see the [root README](../README.md)

## Local deviations from upstream

- **Port 8457** instead of the upstream standalone default 8080 (kit config
  template), loopback only, bearer key required
- **Trial claiming and off-peak channels disabled**: the kit's shipped config
  does not use the upstream `claim` (limited-trial auto-grabbing) or `/async/*`
  (off-peak) features; the underlying defaults are fail-closed (`false`) after
  the audit remediation
- **Vendoring exclusions**: `Android-APP/` (209 MB) and `node_modules/` are not
  vendored; `node_modules/` is installed by setup.mjs via `bun install
  --frozen-lockfile`. The Android build path (`scripts/build-android-apk.sh`,
  the `build:android-*` npm scripts, the esbuild devDependency and the
  `build-android` job in the vendored `.github/workflows/release.yml`) was
  removed with it
- Local changes and tests are tracked in this repository; the
  [vendor patch](../patches/zcode-proxy-local-patches.patch) is a historical
  reference, not a complete record of later changes

## Configuration & environment variables

The proxy reads `config.yaml` by default. For release/source installs the kit
points `ZCODE_PROXY_CONFIG` at `../proxy/config.yaml`; npm installs keep that
config in their separate state directory. Environment variables take
precedence. The common ones:

| Environment variable | Default | Meaning |
|---|---|---|
| `ZCODE_PROXY_PORT` | `8080` | listen port (the kit template uses 8457) |
| `ZCODE_PROXY_API_KEY` | none | key clients must present (in the kit: the `.proxykey` content) |
| `ZCODE_PROVIDER` | `zai` | provider `zai` / `bigmodel` |
| `ZCODE_PROXY_CONFIG` | `config.yaml` | config file path |
| `ZCODE_PROXY_CREDENTIAL_SECRET` | machine-specific | encryption seed for the login credential (fix it when migrating / using Docker) |
| `ZCODE_LOG_FORMAT` | desktop table | `compact` for single-line logs (narrow terminals) |

## Running from source / TUI

After setup in a release install or source checkout has created
`../proxy/config.yaml`, starting the proxy directly from this directory opens
the interactive terminal panel:

```powershell
$env:ZCODE_PROXY_CONFIG = (Resolve-Path ..\proxy\config.yaml).Path
bun run src/index.ts
```

<img src="docs/images/tui-annotated.png" alt="ZCode Proxy terminal panel" width="980" />

The panel has three areas: **login & settings** (provider / plan / login),
**proxy service** (start/stop, current config) and **logs** (one line per
request, live). Press <kbd>s</kbd> to start the proxy; `Status: running` means
it is ready. Buttons are mouse-clickable, and `bun run zcode-proxy --cli serve`
runs headless. Shortcuts: <kbd>s</kbd> start/stop · <kbd>l</kbd> login ·
<kbd>L</kbd> paste-link login · <kbd>o</kbd> logout · <kbd>p</kbd>/<kbd>t</kbd>
switch provider/plan · <kbd>↑</kbd><kbd>↓</kbd>/<kbd>PgUp</kbd>/<kbd>g</kbd>
scroll logs · <kbd>c</kbd> clear · <kbd>q</kbd> quit.

Kit users normally do not need this — `proxy/zcode-proxy-manager.mjs` keeps the
proxy running headless with log rotation.

## Not used by the kit

These upstream features exist in the codebase but are not part of the kit's
shipped configuration: the Android app (excluded from vendoring), Docker
deployment, the `/async/*` off-peak channels and automatic trial claiming
(disabled, fail-closed). See the upstream repository for standalone use.
