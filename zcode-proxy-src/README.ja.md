# ZCode Proxy
[English (original)](README.md) · [Deutsch](README.de.md) · [Español](README.es.md) · **日本語** · [简体中文](README.zh-CN.md)

このコンポーネントは、ZCode Agent Kit に同梱されるローカルモデル
プロキシを提供します。セットアップは Kit が管理し、アシスタントとの
連携は同意を得た場合だけ設定します。

## ZCode Agent Kit での使用

[メイン README](../README.ja.md) に記載されたセットアップとモデルの
コマンドを使用してください。同梱ソースのバージョンとローカル変更は
[コンポーネントマニフェスト](../MANIFEST.md) に記載されています。

`zcode-kit auth login zai --import` は、Desktop の現在の共有ログイン情報を読み込みます。
Desktop 0.16.9 の `credentials.json` が存在する場合は、それが正式な参照元です。
従来の `config.json` にフォールバックするのは、このファイルが存在しない場合だけです。
認証情報の破損、誤ったシークレット、未対応のアクティブプロバイダーでは、黙って
フォールバックしません。アクティブな `zai`/`start-plan` のインポートでは、
`start-plan` に明示的なプラン設定が必要です。`coding-plan` では通常の OAuth ログインを使用します。
インポートはアカウントの作成、利用枠のリセット、API キーの取得・作成を行いません。
[アカウント管理](../docs/ACCOUNT_ROTATOR.md)も参照してください。

プロセス内ソルバーは CAPTCHA ウィンドウを一度に一つだけ実行します。
最初にトークンを一つ準備し、需要に応じて最大四つまで保持します。
従来の並列実行設定はこの処理能力に制限されます。プロバイダーのレート制限による
一時停止は維持され、待機中の処理、キャッシュ無効化、診断ハッシュで回避できません。

`CAPTCHA_CDN_CACHE_TTL_MS` はメモリとディスクの両方の CDN キャッシュを制御します。
既定値は `86400000` ms（24 時間）で、`0` から `2147483647` までの整数のみ有効です。
無効な値はエラーになり、`0` は両方のキャッシュの読み書きを無効にします。
`CAPTCHA_CDN_CACHE_DIR` で独立したキャッシュディレクトリを指定できます。
Kit が管理するプロキシは、両方の環境変数を子プロセスに渡します。ディスクへの書き込みは
アトミックなエンベロープ形式を使い、取得時刻のない古いエントリや途中で切れたエントリは
拒否します。メモリへの昇格時も、元の取得時刻に基づく経過時間を保持します。

診断では、読み込んだ各アーティファクトの来歴をアトミックに記録し、ウィンドウごとに
実際に読み込んだバイト列の SHA-256 ハッシュを示します。来歴が不明な場合は明示します。
`Last-Modified` は過去のバイト列との同一性を証明しません。保存済みのプロバイダー
スクリプトを静的に調べるには、インストール先のヘルパーを使用してください。

```sh
node <installation>/zcode-proxy-src/captcha-compatibility.mjs <saved-script> [retrieval-epoch-ms]
```

取得時刻が分かる場合は epoch ミリ秒で指定します。このヘルパーはファイルを読み、
ハッシュと互換性マーカーを報告するだけです。スクリプトを実行せず、エンドツーエンドの
CAPTCHA 成功を証明するものでもありません。従来の診断用バイトコード VM 書き換え
（`PE_PATCH`）はバンドル破損が再現されたため削除され、機密性のある DBT 引数ダンプ
（`CAPTCHA_DUMP_DBT`）も削除されました。これらのスイッチは使用しないでください。
ソルバー、安全性チェック、呼び出し可能な `show` の代替経路は維持されています。
デバッグ診断はメタデータのみを扱います。

ローカル修正では、変換対象のストリームや JSON エラー応答を解釈する前に gzip、deflate、Brotli を展開します。空または展開できないバッチ応答は、空の成功応答ではなく `upstream_invalid_response` として通知します。プロキシは自身の作業ディレクトリを呼び出し元のワークスペースとして提示しません。`ZCODE_IDENTITY_ENV_CWD` は明示的な上書きとして維持されます。

出力前の一時的な障害（接続拒否やリセット、HTTP 500/502/503/504/524/529、429、公式クライアントが再試行するゲートウェイのエラーコード）は、同じアカウントで待ち時間を増やしながら最大 3 回再試行します。予算は公式クライアントより小さく（基本待ち時間 1 秒で倍増、`ZCODE_PROXY_TRANSIENT_RETRY_UNIT_MS` で設定：基本待ち時間をミリ秒で指定、既定 500、上限 10000。`off` にすると接続が確立しなかった場合の再試行だけを残します）、再試行のたびにアカウントを再確認し、`Retry-After` は 15 秒まで尊重してそれを超える場合はクライアントに渡します。ゲートウェイの判定（クォータ、残高、CAPTCHA、モデル、認証）、リクエストのエラー、出力開始後の障害は再試行しません。強制されたクライアントセッション用の順序付きトランスポートでは、リクエストを書き終えた後の障害も再試行しません。`message_stop` なしで終わったネイティブの Anthropic ストリームには、最後に `api_error` 型の `event: error` フレーム 1 つを付加します（メッセージは `upstream_incomplete`、読み取り失敗時は `upstream_stream_error` を示します）。未完成の最後のフレームは破棄するので、クライアントは無言の途切れではなく解析できる障害を受け取ります。

## セキュリティ

このプロキシは、信頼できるローカル環境での使用を想定しています。
ローカル端末上でのみ実行し、ログイン情報と設定データを保護して
ください。一部のプロバイダー認証チャレンジでは、OS のサンドボックス
なしでプロバイダー提供の JavaScript が実行される場合があります。
ローカル接続でも、そのコードは隔離されません。
[セキュリティポリシー](../SECURITY.md) を確認し、サービスを端末外に
公開しないでください。

## ライセンス

同梱コンポーネントには Kit と異なる条件が適用される場合があります。
再配布する前に[マニフェスト](../MANIFEST.md)と upstream の該当する
通知を確認してください。
