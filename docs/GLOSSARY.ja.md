# 用語集
[English (original)](GLOSSARY.md) · [Deutsch](GLOSSARY.de.md) · [Español](GLOSSARY.es.md) · **日本語** · [简体中文](GLOSSARY.zh-CN.md)

> 本ドキュメントは英語原文の翻訳です。相違がある場合は英語版が正となります。

kit はローカルの ZCode プロキシを動かし、自分のエージェントのハーネスをそれに接続します。この用語集では、`zcode-kit` の出力と kit のドキュメントで使われる言葉を定義します。

## インストールとプロセス

**インストール（Installation）**：
kit の 1 つのコピー（リリース版のインストール、npm インストール、ソースのチェックアウト）で、それぞれが独自の設定、プロキシキー、状態を持ちます。この用語集のほかの項目は、すべてインストールごとに存在します。

**アップストリーム（Upstream）**：
プロキシがモデルへのリクエストを転送する、ベンダーの ZCode サービスです。

**プロキシ（Proxy）**：
インストールのローカル HTTP サービスで、ループバック上で動作します。ハーネスとは Anthropic 形式と OpenAI 形式でやり取りし、アップストリームに転送します。インストールごとに 1 つです。

**プロキシキー（Proxy key）**：
クライアントがプロキシに送る必要があるローカルのシークレットです。セットアップが生成し、`.proxykey` に保存します。

**マネージャー（Manager）**：
プロキシを起動、停止、再起動する kit のコンポーネントです。`zcode-kit proxy start`、`stop`、`restart` はこれを使います。

**所有者の証明（Identity proof）**：
設定されたポートのプロセスが、このインストール自身のプロキシであることを示す、認証付きのヘルス応答です。結果は *ours*（自身のプロキシ）、*foreign*（ポートで別のものが応答している）、*down*（何も応答しない）、*no key*（プロキシキーがないため何も証明できない）のいずれかです。`zcode-kit proxy status --json` は、これを `health` フィールドに `ours`、`foreign`、`down`、`nokey` として出力します。

**pid の記録（Pid record）**：
マネージャーがプロキシの pid と開始時刻を記録するファイル `logs/proxy.pid` です。マネージャーは、この記録と一致するプロセスだけを停止させます。メッセージでは pid ファイル（pid file）とも呼ばれます。

**ハーネス（Harness）**：
プロキシをモデルのプロバイダーとして使うエージェントの CLI またはエディター拡張機能で、Claude Code、Codex、OMP、OpenCode などがあります。ほかのドキュメントではアシスタントとも呼ばれます。

**統合（Integration）**：
ハーネスがプロキシを使うように、同意を得たうえで kit が 1 つのハーネスに書き込む設定です。

**ランチャー（Launcher）**：
`zcode-kit run <harness>` のプロセスです。プリフライトを実行してハーネスを起動します。ハンドオーバーが可能な環境では、その後自分自身をハーネスに置き換えます。それ以外の環境では、ハーネスが終了するまで残り、ハーネスの終了コードを返します。

**プリフライト（Preflight）**：
ハーネスがプロキシを使う前の短いチェックです。プロキシが動いていてインストール自身のものであることを確認し、必要なら起動し、利用枠を確認します。

**MCP ブリッジ（MCP bridge）**：
インストール済みの ZCode Desktop ランタイムのツールをハーネスに提供する MCP サーバーです。これを登録することは、モデルを接続することとは別です。

**トランザクション（Transaction）**：
`setup`、`integrate`、`update`、`accounts enable` などのコマンドを 1 回実行したときのファイル変更の記録で、バックアップを含みます。`zcode-kit rollback [tx-id]` は、最新のトランザクションまたは指定したトランザクションを元に戻します。

**メモリフットプリント（Memory footprint）**：
OS がプロキシのプロセスに割り当てているメモリの量です。プロキシのメモリ上限はこの値で判断します。ランタイムがこの値を取得できない環境では、代わりに常駐セットサイズ（RSS）を使います。

**ハンドオーバー（Handover）**：
ランチャーが自分自身をアシスタントに置き換えることです。アシスタントはランチャーのプロセス ID を引き継ぎ、その横に kit のプロセスは残りません。Node.js 26.1 以降を使う Linux と macOS で行われます。`ZCODE_KIT_RESIDENT_LAUNCHER=1` で無効にできます。

**共有プリフライト（Shared preflight）**：
同じインストールで同時に起動した複数の OMP ウィンドウに対する、1 回のプリフライトです。`logs/omp-autostart.token` を作成したウィンドウがプリフライトを実行し、ほかのウィンドウはその結果を待ちます。

## プロキシのライフサイクルと起動ロック

**起動ロック（Start lock）**：
このインストールでプロキシの起動が進行中であることを記録するファイル `logs/manager.lock` です。保持者は常に最大 1 つです。

**保持者（Holder）**：
起動ロックに、起動を実行しているものとして記録されているプロセスです。

**古いロック（Stale lock）**：
保持者がもう存在しないことが証明された起動ロックです。つまり、保持者のプロセスが終了しているか、その pid が後から起動した別のプロセスのものになっています。単に時間が経っているだけのロックや、保持者を確認できないロックは、古いロックではありません。

**引き継ぎ（Takeover）**：
起動を進めるために、古いロックを自分のロックに置き換えることです。動いている保持者のロックには決して適用されません。

**起動猶予期間（Startup grace）**：
プロキシを起動してから最初の 60 秒間です。この間は、まだ応答しないプロキシが終了させられることはありません。

**孤立したプロキシ（Orphaned proxy）**：
起動したプロセスが中断された後も、正常に動き続けているプロキシです。次の起動は、新しいプロキシを起動する代わりに、所有者の証明によってこのプロキシを引き継ぎます。

**ハングしたプロキシ（Hung proxy）**：
インストール自身のプロキシで、動いてはいるもののヘルスチェックに応答しないものです。kit がこれを終了させるのは、自身のものであり、かつハングしていることの両方が証明された場合だけです。

**ヘルススーパーバイザー（Health supervisor）**：
プロキシの一部で、自身のメインスレッドとメモリフットプリントを監視し、警告するか、再起動を依頼するか、処理を続けるかを判断します。

**自動再起動（Automatic restart）**：
メインスレッドが応答しなくなった後、またはメモリがハードリミットを超えたままになった後に、プロキシ自身がマネージャーに新しい起動を依頼することです。ログの行では respawn と呼ばれます。再起動の予算によって制限されます。

**再起動の予算（Restart budget）**：
マネージャーが一定の時間枠内に受け付ける自動再起動の回数で、15 分間に 3 回です。

**respawn の承認（Respawn acknowledgement）**：
プロキシからの自動再起動の依頼を受け付けたことを示す、マネージャーの記録された確認です。メモリが原因で依頼したプロキシは、この承認を受けてからドレインします。承認がなければ処理を続けます。

**ドレイン（Drain）**：
正常な停止の一段階です。プロキシはリスナーを開いたまま、新しいリクエストを拒否し、実行中のリクエストを期限までに完了させます。

**停止リクエスト（Stop request）**：
マネージャーが自身のプロキシに正常な停止を依頼するための、認証付きのループバックのリクエスト（`POST /__kit/stop`）です。プロキシキーと停止トークンが必要です。

**停止トークン（Stop token）**：
起動ごとに作られるシークレットで、プロキシキーと組み合わせて停止リクエストを認可します。pid の記録に保存され、どのハーネスの設定にも含まれません。

**再起動（Restart）**：
プロキシの停止とそれに続く起動で、`zcode-kit proxy restart` で依頼します。

## CAPTCHA ソルバー

**解決処理（Solve）**：
ヘッドレスのページ内で、ベンダーの CAPTCHA チャレンジを 1 回実行することです。結果はトークンか失敗のどちらかです。

**ソルバー（Solver）**：
プロキシのうち、解決処理を到着順に 1 つずつ実行する部分です。

**ソルバープロセス（Solver process）**：
プロキシがソルバー用に起動するプロセスです。プロキシごとに最大 1 つです。メモリ上限（`solver.memoryCapMB`、デフォルトは 300 MB）があり、可能な環境では OS がこれを強制します。

**入れ替え（Recycle）**：
次の解決処理の前に、ソルバープロセスを新しいものに置き換えることです。メモリ上限の 80 % に達したとき、または 100 回の解決処理の後に行われます。

**フェイルファスト（Fail-fast）**：
10 分間に 5 個を超えるソルバープロセスが異常終了したため、プロキシがソルバープロセスを起動しない期間です。解決処理が必要なリクエストには、HTTP 503 と `Retry-After` が返されます。

## 受け入れ制御

**受け入れ制御（Admission）**：
プロキシがリクエストごとに、リクエストボディをすぐ処理するか、待たせるか、拒否するかを決めることです。

**処理中のバイト数（In-flight bytes）**：
プロキシが現在保持しているリクエストボディの合計サイズです。ボディを読み込んでから、アップストリームが応答するまでの間が対象です。

**バイト上限（Byte cap）**：
処理中のバイト数の上限で、デフォルトは 64 MiB です（`server.admission.maxInFlightMB`）。受け入れ制御の上限はこれだけで、開いているレスポンスストリームには上限がありません。

**受け入れ待ちキュー（Admission queue）**：
受け入れを待っている、まだボディが読み込まれていないリクエストの、長さに上限のある先入れ先出しの列です。待機できるのは最大 64 件で、それぞれ最大 15 秒です。

**拒否（Shed）**：
受け入れられなかったリクエスト、またはドレイン中に届いたリクエストを、呼び出されたエンドポイントのエラー形式で、HTTP 503 と `Retry-After` によって拒否することです。この拒否が利用枠エラーになることはありません。

## アカウント

**Account Rotator**：
許可された複数のログインを別々のアカウントとして保持する、オプションの機能です。[ACCOUNT_ROTATOR.ja.md](ACCOUNT_ROTATOR.ja.md) を参照してください。

**有効なアカウント（Active account）**：
プロキシが現在使っているアカウントで、アカウントの表では `*` が付きます。

**判定（Verdict）**：
`zcode-kit accounts health` が各アカウントに付ける状態で、`ok`、`low`、`exhausted` などがあります。

**利用枠パッケージ（Quota package）**：
ベンダーがアカウントについて報告する残高の 1 つで、残量と合計の単位数、リセット時刻を持ちます。

**クールダウン（Cooldown）**：
利用枠エラーの後、そのアカウントを使わない期間です。

## MCP タスク

**タスクの保持（Task retention）**：
完了した MCP タスクとその結果を、削除するまで保持する期間です。完了したタスクは最大 500 件、最長 7 日間保持されます。タスクの冪等キーは、そのタスクが保持されている間だけ記憶されます。

**再起動の予算（Restart budget）**：
ランタイムが終了した後に、MCP ブリッジが ZCode ランタイムを再び起動する回数の上限で、15 分間に最大 3 回です。予算を使い切ると、ランタイムが必要なツールは、枠が空くまで `HARNESS_RESTART_BUDGET_EXHAUSTED` で失敗します。

## ログ

**プロキシのログ（Proxy log）**：
プロキシとマネージャーが書き込む `logs/proxy.log` です。5 MB でローテーションされ、古いファイルが 1 つ（`proxy.log.1`）残ります。`zcode-kit proxy logs` で読めます。

**回復ログ（Heal log）**：
`logs/heal.log` です。プリフライトとマネージャーが何を見つけて何をしたかを、決まった語彙で短く記録します。プロバイダーのテキスト、パス、認証情報は含みません。

## ターミナルの出力

**レポート（Report）**：
コマンドの回答です。チェックの行と判定の行、状態のテキスト、セットアップの概要、接続情報が該当します。レポートとデータは stdout に出力されます。

**診断メッセージ（Diagnostic）**：
コマンドの回答以外の出力すべてです。進行状況、警告、エラーのブロック、入力の求め、使い方のエラーが該当します。診断メッセージは stderr に出力されます。

**チェック（Check）**：
`zcode-kit doctor` の名前付きのテスト 1 つです。`doctor --upstream` によるアップストリームの比較も含みます。

**チェックの判定（Check verdict）**：
チェックの結果を表す語で、*PASS*、*FAIL*、*WARN*、*SKIP* のいずれかです。コマンドが失敗するのは *FAIL* の場合だけです。*WARN* は動作するものの注意が必要なこと、*SKIP* は該当しないか検出されなかったことを示します。`zcode-kit accounts doctor` は、代わりに独自の語 *OK*、*WARNING*、*ERROR* を出力します。

**処理の結果（Action result）**：
何かを変更する手順（setup、integrate、update、rollback、uninstall）の結果を表す語で、*OK*、*FAIL*、*WARN*、*SKIP*、*INFO* のいずれかです。

**判定の行（Verdict line）**：
チェックのレポートを、チェックの判定ごとの件数としてまとめ、0 以外の終了コードを示す行です。

**接続情報（Connection details）**：
手動で設定するクライアントに、プロキシへの接続方法を伝えるブロックです。ベース URL、キー、モデル ID、プロキシの状態が含まれます。

**行モード（Line mode）**：
全画面のプロキシ TUI 以外のすべての出力です。枠を使わない、プレーンな行で表示されます。

**プロキシ TUI（Proxy TUI）**：
実行中のプロキシの全画面ターミナル表示で、状態のヘッダー、ログのペイン、キーのヒントがあります。

**グリフの段階（Glyph tier）**：
あるターミナルで出力に使える文字の集合で、*full*、*wgl4*、*ascii* のいずれかです。段階によって変わるのは記号だけで、言葉は変わりません。

## サポート

**サポート下限（Support floor）**：
kit がサポートする最も古いランタイムのバージョンで、Node.js 24 です。これより古い場合、インストーラー、`setup`、`update` は何も変更せずに停止します。
